# Updates: November 18, 2026

This update gets the site ready to show archaeological finds on the map. It also makes the map load
from Cloudflare instead of the API, so it stays fast and free however many people visit.

## Artifacts in the database

### What was added

The database can now hold artifacts: inscriptions, coins, ossuaries, buildings, manuscripts, and
other finds. Each artifact records:

- where it was found, and the map place it belongs to
- how old it is
- which museum holds it
- a photo, with the photo's license and the name of the photographer
- what the find shows
- how sure scholars are that it is genuine

Seven artifacts were picked by hand to start:

| Artifact | What it shows |
|---|---|
| Pilate Stone | Pontius Pilate was a real Roman governor of Judea |
| Caiaphas ossuary | Likely the burial box of the high priest's family |
| Temple Warning inscription | The barrier around the Temple's inner courts was real |
| Magdala Stone | Galilean towns had synagogues in Jesus' time |
| Capernaum synagogue | Capernaum was a real Jewish town on the Sea of Galilee |
| Siloam inscription | King Hezekiah's water tunnel is real |
| James ossuary | Not evidence: whether its inscription is genuine is disputed |

The descriptions were written with AI help. They are marked as drafts, so the site will show them
as "Being checked" until someone checks each one against sources.

### Why

The site already labels every statement by where it comes from. Artifacts add physical evidence
from the world the Bible describes.

An object can show that a person, place, or custom was real. It can't prove a matter of faith. So
each artifact says plainly what it shows, and nothing more.

### How it works

Every artifact has an authenticity label: accepted, debated, forgery, or unreviewed. The database
only lets an accepted artifact support a claim. A debated find, like the James ossuary, can give
context to a claim, but it can never be shown as proof of one. If an accepted artifact is later
found to be debated, the database won't allow the change until its links to claims are fixed.

A photo can't be saved without its license and a link to where it came from. That way every photo
on the site can be credited properly.

## Finds from Wikidata

### What was added

A new script reads Wikidata once a week. Wikidata is a free, open database run by the same group as
Wikipedia. For every place on the map, the script looks for finds that Wikidata says were
discovered there. It keeps finds from Bible times through the early Church (up to 700 CE).

The script also fills in the photos and museum details for the hand-picked artifacts, using
Wikidata and Wikimedia Commons. It only fills in empty fields. It never changes what a person wrote.

### Why

Typing in every find by hand would take a long time. Wikidata already links many finds to the
places on the map, and its data is free to use for any purpose.

### How it works

Finds that come from Wikidata are marked "unreviewed." The site will show them as "Being checked"
until someone looks at each one.

The script runs in GitHub Actions, never while a visitor is waiting. It waits between requests and
names the site in each request, as Wikidata asks.

Photos are linked from Wikimedia Commons, not copied. They use none of the site's storage. Most are
shared under Creative Commons licenses that require credit, so the license and the photographer's
name are saved with each photo.

### Good to know

Wikidata knows fewer finds than expected. In a test run, it listed only two dated finds at
Jerusalem, Caesarea, Capernaum, Magdala, and Siloam combined. Hand-picked artifacts will stay the
main source for now.

*Later:* that test run only searched a few places. The first full run on November 23 imported
1,192 finds, most of them far from the Holy Land. See the [November 24 update](2026-11-24.md) for
how that was fixed.

The photo that Wikidata gives for the Siloam inscription shows the Pool of Siloam, not the
inscription. Someone should pick a better photo for it by hand.

Many key finds are held by the Israel Antiquities Authority, which has no public API. Those can be
added by hand to `scripts/seed_artifacts.py`, with a link to the museum's page.

## The map loads from Cloudflare

### What changed

The map's list of places, each place's details, and the artifacts are now saved as files on the
website itself. Once a week, a new GitHub Actions workflow called "Weekly data" saves fresh copies
from the database. If anything changed, it updates the site.

The website reads these files first. If a file is missing, it asks the API instead, as before.

### Why

The API runs on Render's free plan. That plan runs one small server and puts it to sleep after
about 15 minutes with no visitors. The next visitor then waits 30 to 60 seconds. If many people
visit at once, they all wait in line for that one server.

The map's data only changes when an import runs. So there was no reason for every visitor to wake
the server and the database. Cloudflare serves files from all over the world for free, and it never
sleeps. The map now opens quickly even when the API is asleep, and visits to the map don't use the
database's free hours.

### Good to know

The weekly workflow doesn't update the database's tables. After a database change like this one,
someone still needs to run `alembic upgrade head` against Neon. If they forget, the workflow stops
with a message saying so.

Each weekly update also makes Render rebuild the API, even though only website files changed. This
does no harm. It can be turned off in Render's Build Filters setting.

## Finds on the map (added November 20)

### What was added

The map now shows archaeological finds. A find that belongs to a place in the Bible is joined to
that place: its dot turns gold and gets larger, and the place's panel lists the finds next to the verses that
name it. Search results say how many finds a place has. The place or find you have open is a larger bright blue dot, so it's
easy to see where you are. Only a find that isn't tied to any place in
the Bible gets its own gold diamond. Choosing a find opens it in the side panel with:

- its photo, with the photographer, the license, and a link to where the photo came from
- what kind of find it is, how old it is, where it was found, and which museum holds it
- how sure scholars are that it is genuine
- what it shows, and a short description

Each place's panel lists the finds from that place. Finds whose find spot isn't known, like the
James ossuary, are listed under the map. A checkbox hides the finds for anyone who only wants the
places. The Sources page now credits Wikidata and Wikimedia Commons.

New glossary terms explain each kind of find (inscription, coin, ossuary, building, manuscript,
object) and each authenticity label (accepted as genuine, debated, forgery, not yet reviewed).

### Why

An artifact is physical evidence, so a visitor should see it where it was found, next to the
places and verses it relates to. Showing how sure scholars are, every time, keeps a debated find
from being mistaken for proof.

### How it works

Nothing on the page names a particular artifact. The markers, panels, and lists are built from
whatever the database holds. A new artifact, whether added by hand to `scripts/seed_artifacts.py`
or imported from Wikidata, shows up after the next Weekly data run with no code change.

Joining finds to places keeps Scripture and the physical evidence for a place together in one
spot, instead of two markers side by side. When several finds with no Bible place share a spot,
they share one diamond with a number on it. Clicking it again moves to the next find. Either way,
the panel lists the other finds from the same place.

Drafts show "Being checked". Finds imported from Wikidata also say that no one on this site has
checked them yet.
